# Tekmor — 产品需求文档（PRD v1，待确认）

> 作者：晨星 ｜ 状态：Phase 1 调研完成，待用户确认后进入 Phase 2 实现
> 本文件是 ARCHITECTURE.md 的产品侧输入；DEPLOY.md / USAGE.md 是交付使用文档。

## 1. 愿景与定位

**Tekmor**（古希腊语 τέκμωρ = 确证 / 凭证）是一个**本地优先、端到端可验证**的 AI 知识库与智能体平台。核心理念：在完全离线的个人机器上，让 AI 的每一句回答都**锚定到原文证据**，且**可审计、可重建、不可篡改**。

- **MVP 先打通 RAG 链路**：离线知识库检索 + 段落级证据引用 + 哈希链审计。
- **Agent 层（F7 / evolver）延后到 P2**：复用已发布的 aetheros 内核思路，但本轮不实现。
- **不与 SaaS 抢功能**，而是把「可验证」做到极致——这是云端闭源产品做不到的差异化。

## 2. 用户画像（Phase 1 PM 调研）

| 画像 | 描述 | 核心诉求 |
|---|---|---|
| **隐私敏感知识工作者** | 律师 / 研究员 / 医生，手里有大量机密文档 | 文档不出本机、零出站，但能像问助手一样检索 |
| **本地 AI 爱好者 / 极客** | 自己有 16GB 内存的笔记本，想跑得动 | 在有限硬件上可实际运行、可调试、不 OOM |
| **小团队协作** | 3–10 人，共享一份本地知识库 | 单文件 HTML 控制台即可访问，无需部署复杂前端 |
| **审计 / 合规角色** | 需要证明 AI 没有幻觉 | 每条回答可回溯到原文、有哈希链防篡改 |

## 3. 问题陈述

| 痛点 | 现状 | Tekmor 的解法 |
|---|---|---|
| 闭源问答不可信 | 云端 LLM 经常幻觉且无出处 | 段落级证据锚定（AC-04/05/06）+ 无证据不输出 |
| 本地部署门槛高 | 需要 GPU / 编译环境 / 复杂依赖 | CPU-only、预编译 wheel、uv 一键复现 |
| 检索质量差 | 单一向量检索对中文子串弱 | 混合检索 + RRF 二次融合（AC-07/08） |
| 不可审计 | 回答生成后即黑盒 | 哈希链 append-only + verify（AC-09） |
| 资源吃紧 | 16GB 机器跑 LLM 易 OOM | 严格串行 + 驱逐策略 + 内存护栏（AC-14） |

## 4. 目标与非目标

**目标（MVP = F1 + F2 + F3 + F4）**
- F1 离线嵌入 + 内存互斥调度（CPU-only，线程钳 [2,4]）
- F2 混合检索（向量 + 词法 FTS5 trigram）+ RRF 融合 + 重排信号槽
- F3 段落级证据锚定与引用（byte↔utf16 双区间）
- F4 单文件 HTML 控制台（零依赖，HTTP 访问后端）

**非目标（本轮不做）**
- F7 evolver（Agent 自演进）——严格 P2，仅预留聚合层接口
- 多用户鉴权 / 多租户
- 云端同步 / 联网检索
- GPU 加速（780M 无 ROCm kernel，已证伪）

## 6. 功能需求（EARS 格式）

- **FR-1**：系统**应当**在未配置任何云提供商时，ingest→retrieve→cite→answer 全流程零出站请求。
- **FR-2**：系统**应当**在初始化本地推理时把线程数钳制到 [2,4]。
- **FR-3**：系统**应当**为每个被渲染的 claim 附加 citation，解析到具体 chunk id + 字符偏移，可点击回原文。
- **FR-4**：系统**应当**在 claim 无法绑定检索 chunk span 时拦截该 claim（strict 默认），标记 evidence-gap。
- **FR-5**：系统**应当**在 citation 解析到不支持该 claim 的 chunk 时，标记为 citation-unverified，不呈现实为 grounded。
- **FR-6**：系统**应当**在 rerank 启用时，将重排作为第三路信号 w=0.5 与第一阶 RRF 融合，而非直接采用重排顺序。
- **FR-7**：系统**应当**在注入全倒序 reranker 时，最终 top-1 仍是第一阶融合冠军（w 严格 <1）。
- **FR-8**：系统**应当**能完整重建一次会话的输入 / 检索 chunk / LLM 原文 / 最终输出（AC-09）。
- **FR-9**：系统**应当**在文档内容 hash 未变时跳过重嵌（增量索引，AC-10）。
- **FR-10**：系统**应当**在中文查询 top-1 低于相关阈值时回答「未找到相关文档」（AC-11）。
- **FR-11**：系统**应当**支持 `file://` 离线打开控制台 HTML，渲染完整流程（AC-12）。
- **FR-12**：系统**应当**在默认端口不可用时回退 8765/8801/9000，在模型文件缺失时保持 retryable（AC-13）。
- **FR-13**：系统**应当**在 `evidence.mode=lenient` 时，于 UI 与每条 trace 永久标记（lenient 仅可显式开启，AC-14）。

## 7. 验收标准（AC-01..AC-14，同 ARCHITECTURE §6）

| AC | 类别 | 要求（摘要） |
|---|---|---|
| AC-01 | 离线底线 | 未配置云时全流程零出站；出站计数器真实计数（非硬编码 0） |
| AC-02 | CPU 线程 | 初始化本地推理时 `autoThreads()` 钳到 [2,4] |
| AC-03 | 防回退 | 任何改动使 `autoThreads(n)` 返回 [2,4] 之外 → 测试具名失败 |
| AC-04 | 证据锚定 | claim 渲染时附 citation 解析到 chunk id + 字符偏移，可点击回原文 |
| AC-05 | 无证据不输出 | claim 无法绑定检索 chunk span → 拦截，显式 evidence-gap（strict 默认） |
| AC-06 | 引用可信 | citation 解析到不支持该 claim 的 chunk → 标 citation-unverified |
| AC-07 | 检索融合 | rerank 启用时第三路信号 w=0.5 与首阶 RRF 融合（不直接采用重排顺序） |
| AC-08 | 对抗不变量 | 全倒序 reranker 注入时，最终 top-1 仍是首阶融合冠军（w 严格 <1） |
| AC-09 | 轨迹可重建 | 完整重建 输入/检索 chunk/LLM 原文/最终输出 |
| AC-10 | 增量索引 | 文档内容 hash 未变 → 跳过重嵌 |
| AC-11 | 中文兜底 | 中文查询 top-1 低于阈值 → 答「未找到相关文档」 |
| AC-12 | 单文件控制台 | `file://` 离线打开 HTML 渲染完整流程，无需 server |
| AC-13 | 端口/模型降级 | 默认端口不可用 → 回退 8765/8801/9000；模型缺失 → loader 保持 retryable |
| AC-14 | 证据模式可见 | `evidence.mode=lenient` 在 UI 与每条 trace 永久标记（仅显式开启） |

## 8. 成功度量

| 指标 | 目标 |
|---|---|
| 离线验证通过率 | CI 断网 `test:offline` 100% 通过，出站计数恒为 0 |
| 中文检索命中率 | 黄金集 top-3 命中 ≥ 90% |
| 证据拒答率 | 无依据查询拒答率 ≥ 95%（不生成幻觉） |
| 内存峰值（3B 档） | ≤ 2.85GB，无 OOM |
| 一键复现 | 干净环境 `uv sync --frozen` 后 `tekmor doctor` 全绿 |

## 9. 命名与品牌

- **tekmor**（τέκμωρ = 确证 / 凭证）——PyPI 裸名与 npm 裸名双通道均未占用。
- 与 aetheros（αἰθήρ + -os，大气/本质）同源，构成「本质 / 确证」品牌家族。
- 所有代码、文档、提交署名统一为「晨星」。
